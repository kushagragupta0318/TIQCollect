# 2026-09-08 — PINNED DOWN from 9.15.6755, and this is a real trade recorded
# rather than a silent edit. optbinning 0.21.0 (the newest release) requires
# ortools<9.12, so 9.15.6755 + optbinning is an unsatisfiable set and
# `docker compose build api` failed outright with ResolutionImpossible.
#
# 9.11.4210 is chosen because it is what the routing work was ACTUALLY verified
# against: installing optbinning on the dev machine silently downgraded ortools,
# so core/routing.py's plan_route and the tests in tests/test_routing.py
# (16 since plan_fleet was deleted on 2026-09-24) were written and run on
# 9.11, never on 9.15. Pinning
# here makes the declared dependency match the tested one instead of the other
# way round.
#
# THE ALTERNATIVE, which is architecturally better and is not done yet: the
# SERVING path should not depend on a training library at all. The model
# artifact pickles optbinning OptimalBinning objects, so unpickling drags
# optbinning (and therefore its ortools ceiling) into the API container. Storing
# the binning as plain edges + WOE arrays would remove the dependency from
# serving entirely and free ortools to move independently.
ortools==9.11.4210
